# Развёртывание

Полная последовательность сборки — в README. Доступ к Docker может требовать sudo или членства в группе docker. Сначала получите runtime-data из проверенного архива, затем выполните build.sh. verify_runtime.py проверяет размер и SHA256 всех обязательных файлов. Для работающего локального проекта stage_runtime.py собирает архивные файлы из существующих путей; при развёртывании на новом сервере этот шаг заменяет скачивание архива.

run.sh создаёт собственную конфигурацию HTTP Basic с PBKDF2 SHA256 и солью, затем запускает один контейнер. Конфигурация монтируется только для чтения, результаты хранятся на хосте в .runtime. Образ не содержит паролей и исходных исследований. Контейнер работает с UID/GID запускающего пользователя. Для публичного сервера подключите домен и HTTPS reverse proxy к 127.0.0.1:8095; порт приложения напрямую в интернет не открывайте. Команда разместила прототип по адресу https://app.betterimaging.ru/. Скрипт локального запуска сам не настраивает этот домен или DNS.

Авторизация защищает сайт, API, изображения, Swagger и /health. HEALTHCHECK проверяет доступность HTTP-сервера по ожидаемому ответу Basic challenge; он не проверяет точность моделей. Реальную готовность подтверждает обработка контрольного набора. Веса загружаются при первом анализе, поэтому первый запрос медленнее следующих.

Переменные: DXA_PORT — порт скрипта запуска; DXA_CONTAINER_NAME — имя контейнера; DXA_JOBS — каталог задач внутри приложения; DXA_RETENTION_HOURS — срок хранения; DXA_JOBS_QUOTA_BYTES — квота задач (по умолчанию 8 GiB). Не используйте несколько workers без переработки очереди.

После запуска: проверить вход, загрузку бедра и позвоночника, XLSX, ZIP и обработку повреждённого файла. Развёртывание можно проверить без сети после сборки — все веса уже включены. Журналы: docker logs imagelab-dxa. Остановка: docker stop imagelab-dxa. Повторный запуск не удаляет .runtime.

Проверка программных правил: python -m unittest discover -s tests -p 'test_prototype*.py' и test_anatomy_measurements.py в окружении с зависимостями. Результаты проверки контейнера и полный повторный прогон приведены в reports/RESULTS.md.
